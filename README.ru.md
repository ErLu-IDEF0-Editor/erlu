# erlu

**Редактор функциональных моделей IDEF0 и диаграмм потоков данных DFD для desktop и браузера, написанный на Rust с интерфейсом egui.**

erlu помогает описывать функции системы, их входы, управления, выходы и механизмы. Начните с контекстной диаграммы и постепенно раскрывайте модель через декомпозицию.

Программа предназначена для аналитиков, инженеров и архитекторов, использующих IDEF0 для изучения и проектирования процессов. Разработчики могут расширять редактор WASM-плагинами и подключать внешние инструменты и AI-агентов.

## Возможности

- **Моделирование IDEF0:** функциональные блоки, ортогональные стрелки, ветвления, декомпозиция, наследуемые интерфейсы, туннели и ссылки на функции.
- **Единая история изменений:** Undo/Redo сохраняется при навигации и распространяется на действия интерфейса, AI и плагинов.
- **Проверка модели:** диагностика структуры, связей, нумерации и семантических правил IDEF0.
- **Стоимостный анализ:** стоимость функций и расчёт по декомпозиции.
- **Экспорт:** PDF, SVG и Markdown.
- **Оформление:** светлая и тёмная темы, цвета объектов, интерфейс на английском, русском, французском, испанском, арабском и упрощённом китайском языках.
- **Автоматизация:** MCP на desktop и коннектор внешнего агента в браузере.

Встроенные проверки помогают находить ошибки, но не являются полной сертификацией соответствия стандарту. См. [область валидации](docs/validation.md).

## Desktop и web

Desktop-версия предназначена для Linux, Windows и macOS. Браузерная версия использует то же ядро модели, истории, проверок и экспорта.

Документы обрабатываются локально. Для редактирования в браузере не нужны учётная запись и серверная база документов. Файлы открываются через диалог выбора и сохраняются скачиванием. Предусмотрены восстановительная копия в IndexedDB и работа офлайн после установки кэша приложения. Восстановление не заменяет сохранение файлов.

Локально проверены Linux/NixOS и браузеры Chromium, Firefox и WebKit. Статус остальных платформ и браузеров описан в [журнале приёмки](docs/acceptance.md).

## Плагины

В поставку входят три WASM-плагина:

| Плагин | Назначение |
| --- | --- |
| Colors | Цвета выбранных блоков и стрелок |
| [Responsibility Map](plugins/responsibility_map/README.md) | Организационные роли, распределение ответственности, проверки и экспорт RACI |
| [Semantic Dictionary](plugins/semantic_dictionary/README.md) | Понятия и синонимы, привязка к стрелкам, поиск использований и согласование подписей |

Один WASM-компонент работает на desktop через Wasmtime и в браузере через Worker. Плагины добавляют команды, проверки, экспортёры и формы ввода.

Изменения проходят через общий транзакционный движок и поддерживают Undo/Redo. Первая версия SDK не предоставляет регистрацию новых нотаций и произвольных виджетов.

## Быстрый запуск из исходников

### Nix / NixOS

Из корня репозитория:

```sh
nix-shell
npm --prefix web ci
npm --prefix web run plugins
```

Соответственно: запуск desktop, открытие примера или запуск web по адресу `http://127.0.0.1:8080`:

```sh
cargo run -p erlu
```

```sh
cargo run -p erlu -- examples/order-fulfilment.idef0
```

```sh
trunk serve
```

Nix-shell предоставляет инструменты сборки и runtime-библиотеки. Устанавливать Trunk повторно через Cargo не нужно. Отдельный каталог компилятора предотвращает смешивание артефактов Nix и rustup.

### Без Nix

Нужны Rust, Node.js 22+, Python 3, Trunk и wasm-tools. Версия Rust закреплена в `rust-toolchain.toml`.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-tools --version 1.263.0 --locked
cargo install trunk --version 0.21.14 --locked
npm --prefix web ci
npm --prefix web run plugins
```

Затем используйте команды запуска выше. На Linux также нужны библиотеки X11/Wayland, libxkbcommon и OpenGL.

## Основные действия

| Действие | Управление |
| --- | --- |
| Добавить блок | Правая кнопка мыши |
| Создать стрелку | Перетаскивание от порта или границы диаграммы |
| Создать ветвление | Ctrl + перетаскивание от стрелки |
| Изменить свойства | Двойной щелчок |
| Открыть декомпозицию | Средняя кнопка на блоке |
| Подняться на уровень выше | Средняя кнопка на фоне |
| Отменить / повторить | Ctrl+Z / Ctrl+Shift+Z |
| Вписать диаграмму в окно | F |

На macOS стандартные команды редактирования используют Cmd.

## AI и автоматизация

Подключите MCP-клиент к отдельному процессу или управляйте документом открытого desktop-окна:

```sh
cargo run -p erlu -- mcp --headless
```

```sh
cargo run -p erlu -- --mcp
```

Параметры подключения доступны в меню **AI**. Изменения используют общую историю и проверки. Сохранение на диск выполняется явно.

В браузере агент подключается через [JavaScript/TypeScript SDK](web/sdk/erlu-agent.js). Пользователь разрешает доступ для конкретного origin и может его отозвать. Адаптер агента предоставляет интеграция; встроенный AI-чат не требуется. См. [AI API](docs/ai.md).

## Для разработчиков

| Крейт | Ответственность |
| --- | --- |
| `erlu-core` | Модель, команды, транзакции, история, проверки, геометрия и экспорт |
| `erlu-app` | Интерфейс egui, desktop/web-адаптеры и MCP |
| `erlu-plugins` | Загрузка и выполнение WASM-компонентов на desktop |

GUI, MCP, браузерный коннектор и плагины используют общий реестр действий. Проверки ревизий обнаруживают конфликты при асинхронном редактировании.

Документы сохраняются в JSON-формате `.idef0` с независимой версией и явным списком возможностей. Предусмотрены реестр миграций и сохранение неизвестных необязательных данных. Старые Qt-документы и бинарные Qt-плагины не поддерживаются.

DFD сохраняется в самостоятельных документах `.dfd`. Доступны обозначения Гейна — Сарсона и Йордона — ДеМарко, декомпозиция, словарь данных и проверка баланса потоков. См. [руководство DFD](docs/dfd.md) и [пример обработки заказа](examples/order-fulfilment.dfd).

### Проверки и сборка

```sh
cargo test --workspace --locked
cargo build -p erlu --release --locked
trunk build --release --locked
npm --prefix web test
```

Web-сборка находится в `dist/web` и может размещаться на статическом HTTPS-хостинге. [Релизный workflow](.github/workflows/release.yml) собирает desktop-архивы, web ZIP и контрольные суммы. Он рассчитан на GitHub Actions; для Forgejo нужна адаптация CI. Удалённые релизные workflow пока не запускались.
